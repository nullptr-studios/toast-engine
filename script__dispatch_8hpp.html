Detailed Description

Queue of Lua work that could not run right away because its interpreter was busy.

Author
Xein
Date
5 Oct 2026

A thread that owns one interpreter never waits for a second one, see LuaState. When a script calls into a node whose interpreter is busy on another thread the call is queued here and delivered later by a thread that owns nothing: between tick waves, after the event queue was polled and at the end of the frame
