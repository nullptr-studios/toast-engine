Detailed Description

Runs a plan of jobs on the thread pool, one interpreter per job.

Author
Xein
Date
6 Oct 2026

Whatever has to run Lua on one interpreter is one job, and a job's items run one after the other, so an interpreter is only ever used by one worker at a time and nothing waits for another worker's interpreter. The tick waves, the construction of scripts in a prefab and the init/begin of a tree all run through here
